Check your own data

Before you deposit a dataset, check it against your paper. The encore command runs the same check as the registry, on your own machine: agents read the paper, write down each of its claims, and test the claims on the data. You get an outcome for every claim and a list of what is wrong with or missing from the dataset.

Run a check

pip install encore-science

encore check ./nwb/ --paper paper.pdf                    # a directory of files, before you upload them
encore check s3://bucket/smith-2024/ --paper paper.pdf   # files at a URL
encore check DANDI:001234 --draft --paper paper.pdf      # a dataset in an archive

A quick check, the default, takes one to three hours: a reader writes the claims from the paper, a second reader checks them, and an author tests them on the data. --full adds two rounds in which an independent agent verifies the work, and takes several hours more. If a run stops, run the same command again and it goes on from where it stopped.

Requirements

  • Claude Code, signed in to a Claude account or with an API key. The run counts against that account's usage.
  • Python 3.10 or later, and git.
  • The paper, as a PDF or a text file. A preprint is fine.

The report

The run writes report.md, which lists every claim with its outcome (reproduced, partially reproduced, not reproduced, or blocked) and every finding about the data, and points to the notebooks that tested them. A failure to reproduce may be the agent's: read the notes and the notebooks before acting on one.

On your own machine

A check you run yourself stays on your machine. The agents' commands run in a sandbox: they can write only inside the run's directory and can reach only the archives, Python's package index, GitHub and doi.org. A local dataset is read in place and never changed.
