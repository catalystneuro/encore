Load every session¶

One file per subject (the +ogen.nwb file where a session has one, as ring/data.py get_session_info chooses; at this version each subject has exactly one file), in the code's sorted order, which fixes the session index. For each file the epochs, the head direction and the units table are read; spike times are read for the head-direction units only. The cross-validated tuning curves are computed as ring/data.py process_file does (helper, tuning_curves_session).

Recordings deposited more than once, and the shared clock¶

Duplicates: the number of head-direction samples and the first spike time of the first unit are compared across sessions. Clock: for every session, the head-direction information of the plain (unsmoothed) tuning curves of its head-direction units over the square epoch is computed with the spike times shifted by a lag between -2 s and +2 s. If spikes and head direction share a clock, the information peaks near lag 0 (a head-direction cell's tuning is sharpest at a lag of a few tens of ms, its anticipatory time interval).

def info_at_lag(d, lag):
    hd_idx, ti = d["hd_idx"], d["ti"]
    N = len(hd_idx); ok = hd_idx >= 0
    occ = np.bincount(hd_idx[ok], minlength=100).astype(float)
    vals = []
    for st in d["sess"]["spikes"]:
        c = H.spike_counts(st + lag, ti, d["tf"], N)
        r = np.bincount(hd_idx[ok], weights=c[ok], minlength=100) / np.maximum(occ, 1)
        p = occ / occ.sum(); lam = (p * r).sum()
        if lam <= 0: continue
        q = r / lam
        vals.append(np.nansum(p * q * np.log2(np.where(q > 0, q, 1))))
    return np.mean(vals)

fig4-generative-fit¶

A single parameter set of the generative process, fitted to the two-point correlation function pooled over mice, is (sigma, beta, b) of about (1.42, 2.77, 1.73).

The grid is the criterion's (ring/gp_opt.py: sigma in linspace(1, 2, 20), b in linspace(0.01, 5, 30), beta in linspace(0.01, 10, 30); error over the first 20 coefficients). The criterion asks for 500,000 samples per evaluation; on this runner's CPUs that is about 3 hours for the 18,000 points. So the whole grid is first evaluated with 25,000 samples, the same draws for every point (common random numbers, float32 as the paper's torch run on a GPU), and the 30 best points are then evaluated again with 500,000 fresh samples each, which decide the minimum. This is a deviation, recorded in the attempt; the shortlist pass and the final pass are both shown. As variants: the 90 best points at 500,000 samples under the claim's seed, a float32 final pass over the 30, and the paper's own cached error grid (grid_search_results.npz in the Zenodo record, the same grid).

def bump_track(tc_full, counts, hd_raw, sel=None):
    fac = 1.0 / (tc_full.mean(1) + 1e-12)
    Xc = tc_full * fac[:, None]
    nb = len(counts) // 10
    cc = counts[:nb * 10].reshape(nb, 10, -1).mean(1) * fac[None, :]
    m = Xc.T @ cc.T / len(fac)                       # (100, nb)
    peak = (m.argmax(0) + 0.5) * 2 * np.pi / 100
    hh = hd_raw[:nb * 10].reshape(nb, 10)

    err = H.circ_diff(peak[ok], hm)

Differences from the paper's method. The generative fit evaluates the whole grid with 25,000 samples and only the 30 best points with 500,000, where the paper uses 500,000 at every point; random draws come from each claim's seed, not numpy seed 42; the Poisson likelihood that picks the smoothing width drops a term that does not depend on the curve.

The dataset.
