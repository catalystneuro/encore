Reproducing Gable et al. (2026), Figure S4 and Table 5, from DANDI:000010¶

Paper. Gable J, Newman ZL, Young S, Scheib J, Bliese S, Miller N, Kerlin A (2026). Tuft dendrite spikes are accompanied by selective input from distinct functional networks. J Neurosci 46(38) e0974262026, doi:10.1523/jneurosci.0974-26.2026. The claims file (claims/gable-2026.yaml) was written from the version of record (PMC13612898) with its supplement, and from the paper's code, github.com/kerlin-lab/Gable_2026 at commit 688e662.

Dataset. DANDI:000010, version 0.220126.1905, "A motor cortex circuit for motor planning and movement" (Li, Chen, Guo, Gerfen and Svoboda 2015). The paper reuses its silicon-probe recordings of ALM for Figure S4 and Table 5 only. It cites the dataset without a version. 0.220126.1905 is the only published version; the draft holds the same 158 assets (same paths, asset ids and sizes, checked below) and differs only in dandiset metadata, so the published version is pinned.

What can be tested. The four claims on the silicon-probe recordings (figs4-*). Every other claim rests on the paper's own two-photon imaging, which is not in this dataset nor in any public archive the paper or its code names. The claims file marks them data: dataset, and they are blocked as data_missing (a reader's answer in questions/gable-2026.yaml changed them from data: elsewhere).

30 imaging claims (fig1 to fig5, figs1 to figs3, table1) no, blocked (data_missing): the imaging data are not public

Method. The claims file's E1 to E8 (selection, binning, trial-specific activity, population coupling, pairs, bootstrap test) are implemented in alm_coupling.py, whose docstring says where each parameter comes from. The open details O1 to O3 are run under every reading:

  • O1 (a) all high-quality units of a selected session, (b) only those above 0.5 Hz;
  • O2 (a) rate over the time each unit was observed, (b) rate within the analysis windows;
  • O3 (a) only the four trial types CL, CR, IL, IR, (b) all trials with sample and GO times.

Each combination is written as three letters, aaa to bbb. A fourth detail, which the claims file does not name, is how to treat units stored twice in a file (see the data check): counted once (baa) or every stored row kept (baa-r). All sixteen combinations are run through every claim.

The paper's code at commit 688e662 is read for its printed outputs (FigureS4.ipynb: the neurons per session and the pair counts per bin), which are compared with each reading; it is an input of the attempt, fetched from GitHub at the pinned commit.

Clock check¶

The spikes and the trial events must share a clock. ALM activity predicts the instructed lick direction after the sample cue and most strongly after GO (Li et al. 2015), and should not predict it before the sample cue. The instructed side of correct trials is decoded (nearest class mean, five interleaved folds, balanced accuracy) from each unit's spike count in windows relative to sample onset, in every selected session of reading baa (adopted below); as a control each trial takes the next trial's label.

Population coupling and same against different coupling range¶

The three remaining claims share one computation (E4 to E8) and differ in the bins they judge. No reading matched the selection claim, so, as the claims file directs, every reading is run and shown. A claim's outcome is the one all readings give. Where they differ, the outcome is taken under an assumed reading only for a detail with a basis in the paper, its code or the data:

  • Units stored twice are counted once (baa). The two rows of such a unit hold the same spike train under one id, so they are one recorded unit, and the protocol counts a recording deposited twice once. Every reading is also run with every stored row (-r), and how the duplicated rows enter the result is shown below. The paper's code does not show which the authors did.
  • O1 (b), only the units above 0.5 Hz: the code's printed output gives 18 to 25 neurons per session, which the O1 (b) readings give and the O1 (a) readings do not (up to 34).
  • O2 and O3 have no such basis. "Session-wide firing rate" (Methods, Secondary analysis) can be the rate over the recording, (a), but the same paragraph says the coupling was "estimated session-wide from activity recorded between the tactile stimulus onset and 2 s after the GO signal", which reads as (b). TSA is defined on CL, CR, IR and IL (Methods, Activity extraction), which supports O3 (a), but the claims file allows (b), and the code's output cannot tell them apart. Where an outcome depends on O2 or O3, the claim is blocked as methods_underspecified.

An earlier version of this notebook adopted every stored row (baa-r); the verifier's second round found that reading unreasonable, as the duplicated rows are not distinct neurons. With units counted once, the lowest and high coupling claims turn on O2 and O3, and the verifier's third round agreed that both are blocked.

Each claim takes its own bootstrap generator, seeded from the claim, and is repeated under the four further seeds (claim seed plus 1000 to 4000). The distribution of population coupling and the seven bin edges are printed first.

How the analysis differs from the paper's. The step that builds the paper's per-session arrays from these files is not in its code, so the unit filter (O1), the rate (O2), the trial set (O3) and the treatment of units stored twice are run under every combination. The adopted reading baa counts each unit stored twice once and keeps only units above 0.5 Hz; O2 and O3 are not assumed, and the window is a fixed 4.6 s from sample onset (O5). The selection does not reach the paper's 11 mice and 20 sessions under any reading, so the population differs from the paper's, which bears on the three test claims.
