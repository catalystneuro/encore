Reproducing Strickland and McDannald (2022) from CRCNS bst-3¶

Paper. Strickland JA, McDannald MA (2022). Brainstem networks construct threat probability and prediction error from neuronal building blocks. Nature Communications 13:6192. doi:10.1038/s41467-022-34021-1. The claims file (claims/strickland-2022.yaml) was written from the version of record (PMC9582012) with its Supplementary Information and Source Data workbook.

Data set. CRCNS bst-3, doi:10.6080/K0Q23XGR, "Neuropixels recordings from 21 brainstem regions in rats during fear discrimination", read from the public bucket (crcnsarchive/bst-3/live/data.zip, 367,964,637 bytes, last modified 2026-02-11). CRCNS data sets are not versioned, so the version is recorded as unversioned; the MD5 sums of the bucket's checksums.md5 are printed below (data.zip 4ee6c433f5255693d5e85bcca6819cd4), so that a later change can be detected. The paper cites the data set by its DOI and no version; there is only the one published copy (live/, descriptor version 0.6 of 2022-11-29), so it is the one pinned.

What the data set holds. One MATLAB file per single unit (1812, spike times and the session's cue, shock, poke and pellet times, in samples at 30 kHz), the cube file the paper's cubeScript.m builds from them (binned and normalized firing per trial, suppression ratios, region and coordinates per unit), and the paper's five analysis scripts. It holds no cluster membership.

Outside input. The paper's own cue and outcome clusters (L1) come from its Source Data workbook (supplementary file 41467_2022_34021_MOESM4_ESM.xlsx of doi:10.1038/s41467-022-34021-1, streamed from the publisher, MD5 checked), matched to the units by their firing rows (claim source-data-cluster-link). It names clusters for units the data set already holds; it brings in no measurement. The analyses run on the data set's data.

The paper's code. The scripts in the data set (data/scripts) are the code the paper's Code availability points to. Where the Methods leave a detail open and a script settles it, the script is followed and cited (see the docstring of bst3.py).

How the analysis differs from the paper's. It runs in Python on the cube file and the spike times, following the paper's MATLAB scripts where the Methods leave a detail open: the normalization of cubeScript.m, the 1-s and 500-ms bins of the scripts' matrices, the regression with an intercept on cluster mean firing, the shuffles of the contribution and lesion analyses. The cue hub measure uses r squared, the measure the Methods name; with r that outcome would be lower. The outcome networks are judged with r, as their criteria say; with r squared both would be reproduced. The independence of cue and outcome network membership is judged on the paper's own membership; under this attempt's k-means it would not hold. The danger latency is searched within the 10-s cue as the Methods say; no reading tried reproduces the Source Data latencies, and no script computes them. This attempt's own k-means (L2) is reported as the median over 20 seeds where a claim's test turns on it (fig2c-pc1-contribution, cue-outcome-membership-independent); the best of the 20 is a variant elsewhere.
