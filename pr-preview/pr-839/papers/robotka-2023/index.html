Summary: The paper's main decoding findings held up in this data, but only under the methods of the authors' code, whose cross-validation tests trials of exemplars it was trained on and differs from the Methods. Under it, ensembles of 20 units decode call types at 43% (paper 42%), better with the temporal pattern of responses, and decoding rises with the volume the units' receptive fields span and falls with neural variability. Unit counts held, though fewer units passed the good-unit cut. Whether neural clusters follow call types more than acoustic clusters could not be tested, as the vocalization database is not public, nor could brain areas be compared, since no unit's area is recorded. The anesthetized dataset was not analysed.

Notes on the paper

What the attempts found about the paper itself: a method or rule it does not give, a place where it disagrees with itself, published code that does something else. What they found about the data is on each dataset’s page.

  • Methods not availableQuestion for the authors. The STAR Methods describe the decoder's cross-validation as holding out, for each call type, the responses to one exemplar stimulus, while the code (decoders.naiveBayes) holds out one random trial of every stimulus. The two differ here by about 11 points of PCC for ensembles of 20 (32.0% against 43.2% with Z+T), and only the code's scheme gives the paper's values. Which scheme produced Figures 4 and 5? The code's scheme tests trials of exemplars it was trained on: on synthetic units with exemplar-specific responses and no call-type signal it gives 78% where the Methods' gives 10%. This attempt assumes the code's.
  • Published code disagreesThe Methods define the per-call-type response zCT as the average of the trial z-scores; the code computes mean(d)/sd(d) within the call type, and Figure 3C is built from the code's values. Under the Methods' definition song, not distress calls, has the highest average response.
  • Published code disagreesThe Methods compute the MPS on the first 500 ms of the stimulus and use the first three linear discriminant dimensions; the code takes 500 ms before to 500 ms after onset, and takes numpy eigh's first three eigenvectors of the non-symmetric matrix pinv(within) times between, which eigh orders by ascending eigenvalue. Only the code's choices give the paper's R2adj of about 0.1 for the volume here. This attempt adopts the code's choices for Figure 5E and the multiple regression, as the paper's printed values come from them.
  • Selection not documentedThe 1,746 ensembles of Figure 5 are those of the 1,800 with PCC above 30% (GenerateMLFilters.ipynb, pcc > 30); the Methods do not state the filter.
  • Methods not availableQuestion for the authors. The good-unit selection (single-unit PCC Z+T above 12%) uses one random held-out draw, and the count moves from 87 to 101 between seeds here. How was the paper's count of exactly 100 obtained, and is it expected to be stable?

✓Reproduced The dataset holds the awake playback experiment the paper describes, four birds (ZF4F, ZF5M, ZF6M, ZF7F) and 110 distinct stimuli labelled with the 10 call types in the paper's numbers.
The files hold 4 birds (ZF4F, ZF5M, ZF6M, ZF7F) and 110 distinct vocalization stimuli, with Be 12, LT 13, Th 5, Di 5, Ag 9, Wh 13, Ne 15, Te 15, DC 14 and So 9, equal to the paper's counts for every call type. Each stimulus waveform is identical in every unit that heard it. The files also hold 60 song, spectrally filtered and temporally filtered song stimuli with no call type.

◐Partially reproduced The 100 good units that the paper's code lists by name (recording site and pickle file) are units of the dataset, and each is an auditory unit with all 110 stimuli there.
Units are matched by site folder and pickle name. 91 of the 100 good units listed by decodingCallTypesNaiveBayesPart2.ipynb are in the dataset, and all 91 are auditory with all 110 stimuli here (printed in the following data-check cell). The 9 others come from a site folder named ZF4F_2t_190613_101015.old. The dataset's ZF4F_2t_190613_101015 holds 18 pickles, none with those names, so that site was deposited from a different spike sorting than the one analysed. The names are used only here and in variants of fig4b-ensemble-20 and figs4-per-bird-and-sex. The 91 held by the dataset are ZF4F 34, ZF5M 19, ZF6M 16 and ZF7F 22, so all 9 missing units are of ZF4F. The 9 missing units are on electrodes 8, 11, 16, 19 and 20, all of which have pickles in the dataset's site (e8-c8, e11-c33, e16-c33, e16-c35, e19-c46, e20-c61 and e20-c63 are auditory there, with single-unit PCC Z+T 8.3 to 13.5% against the code's 13.0 to 17.7% for the missing ones), but cluster numbers differ and the .old sorting is not deposited, so the units cannot be matched by spike train.
