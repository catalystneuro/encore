Reproducing Guan, Aflalo et al. (2022) from dandiset 000147¶

Paper: Guan C, Aflalo T, Zhang CY, Amoruso E, Rosario ER, Pouratian N, Andersen RA (2022). Stability of motor representations after paralysis. eLife 11:e74478. doi:10.7554/eLife.74478. The paper is open access, and its full text, figure legends and methods were used (eLife, PMC9555862).

Data: DANDI:000147, version 0.221122.2256, streamed from the archive. The dandiset has two published versions, 0.220913.2243 and 0.221122.2256, with the same ten assets (same asset IDs and sizes). The later version is used because its metadata names this paper; the earlier one names the bioRxiv preprint. The authors' download script pins the earlier version, so the files are the ones the authors analysed.

What can and cannot be tested¶

The paper records from a Utah array in the posterior parietal cortex (PC-IP) of one tetraplegic participant, NS, over ten sessions on nine days, while she attempted to press the cued finger (thumb T, index I, middle M, ring R, pinky P) or did nothing (No-Go, X). The dandiset holds the main task of all ten sessions: sorted units, the cued finger, the online decoder's output, the index of the cue's grid position, the run and the trial number. It does not hold the calibration task, the no-movement control task, waveforms or sorting quality metrics. The fMRI and component model RDMs the paper compares against are not in the dandiset; the two fMRI models are in the authors' code repository and are read from there at the commit the paper archived.

Does the trial clock line up with the spikes?¶

The trials table gives a start time and a stop time 3 s later, with no description. The paper's window is defined from the cue. If the start time is the cue, the cued finger should be undecodable before it and become decodable a few hundred milliseconds after it, once the participant has looked at the cue and begun the movement. The cell below decodes the finger from 200 ms windows in each session separately (six classes, chance 1/6).

Checks of the description against the data:

  • Counts. Ten files from one subject, all described as the main task, with 336 to 480 trials in runs of 48 (eight of each condition) and 88 to 110 units. The six conditions are balanced in every session. These match the paper's design (Methods, "Finger flexion grid task").
  • Subject. The files call the participant P1; the paper calls her NS. The dandiset's single subject and the ten session dates match the paper's sessions.
  • Decoder output. In the first session (2018-09-10) the online decoder never output X, as the paper says. That session has 64 No-Go trials. The paper says 84, but its own total of 4016 scored trials is 4080 minus 64, so the data agree with the total and the 84 is a typo.
  • Trial structure. Every run has 48 trials in four screens of 12 consecutive trials, and every one of the 340 screens cues each of the 12 locations once and each condition twice, as the methods describe (the methods say three to four screens per run; here every run has four).
  • Clock. The trials table describes the start time only with the NWB default ("Start time of epoch, in seconds"), so the data have to show what it marks. In every session the finger is at chance before the trial start (mean accuracy 0.15 to 0.19 in windows ending at or before it, highest single window 0.25, against 1/6), first exceeds 0.4 in the window centred at 0.6 s, and peaks between 1.0 and 1.5 s, in all ten sessions. This is consistent with a start time at the cue onset and with spikes on the clock of the trials table, but it does not pin the start time to the cue: a shift of a few hundred milliseconds would look much the same.
  • Observation intervals and epochs. Every unit has the same observation intervals, one per run; every trial's analysed range lies inside one, and every run lies inside its epoch.
  • Spike times are not in ascending order within units. Within a unit, the spikes of the first few seconds of each run are stored before the rest of the previous run. No trial's analysed range meets a span where this happens, because the first trial of a run starts about 6 s into it, so sorting the spike times, as done here, gives the same counts. Tools that assume sorted spike times (for example a binary search over them) could still be misled near run boundaries.
  • Cue location is described as the "screen location (index) where text cue was displayed", an index from 1 to 12 on the grid of three rows and four columns, with no map to the grid or to screen coordinates. The trials table's Run and TrialNumber columns read "no description".
  • Units. The units table holds spike times, observation intervals, electrodes and electrode groups only: no waveforms and no sorting quality metrics.
  • Model RDMs. Each of the three model files stores its condition order, and it is T, I, M, R, P in all three, the order used here.
  • Electrodes. The location is given as PC-IP; coordinates and impedances are missing (NaN).

Claim fig3b-confused-pairs-no-increase¶

"The middle-ring and ring-pinky distances did not increase over the course of the experiment (across sessions: t(8) = −4.5, one-tailed t-test p > 0.99, BF = 0.03; across runs within sessions: t(82) = −0.45, one-tailed t-test p = 0.67, BF = 0.12)." Following the methods, an RDM is computed for each run of each session and its distances are regressed on finger pair, session index and run index. As in the paper, the degrees of freedom of each test are the number of RDMs it rests on minus two: sessions for the session term, runs for the run term. Three variants are shown: the session term from the ten session RDMs; the run term with a separate intercept per session; and both terms from per-run RDMs whose noise covariance is estimated from the whole session. The last variant is there because a run's five folds hold only one or two trials of each finger, so a fold's own noise covariance rests on few residuals and inflates the per-run distances. Bayes factors are not computed.

How this analysis differs from the paper's:

  • The fMRI model RDMs come from the authors' code repository, not from the dandiset.
  • Offline classification is shown with leave-one-out cross-validation (the paper's methods) and with the authors' code (eight folds, a firing cutoff, z-scoring); they differ by one point.
  • The noise covariance of the crossnobis distance uses OAS shrinkage, as the authors' code does; the paper names Ledoit-Wolf.
  • The fraction of errors that are middle-ring or ring-pinky depends on whether errors involving No-Go count; the paper does not say, and only the count without them matches.
  • The FDR family for tuning is not stated; the main reading pools all units and fingers.
  • WUC p-values come from resampling sessions here; the paper used rsatoolbox's bootstrap t-test. Bayes factors are not computed.
  • The paper's code for the session and run regressions is not in its repository. The degrees of freedom follow the paper's stated rule, and the per-run RDMs use the same five-fold estimate as the session RDMs, with a variant using the session's noise covariance. A run's folds hold one or two trials per finger, so the fold covariance is poorly estimated and inflates the per-run distances; the significance of the all-pairs session decrease depends on this choice.
  • The paper's t(6) for the session by model interaction is not explained; three specifications are shown.
  • The gaze regression is run under two assumed orders of the grid index, with and without a ridge penalty; the claim stays blocked.
  • The 12-class cue-location classifier uses eight folds; the paper does not say how it cross-validated it.

What was found about the dandiset:

  • It holds the main task of all ten sessions and matches the paper's counts exactly. The calibration task, the control task, waveforms and sorting quality metrics are not included, and the model RDMs the main comparisons rest on are not in it.
  • Spike times are not in ascending order within units: the first seconds of each run are stored before the rest of the previous run. No analysed trial range is affected once they are sorted.
  • The cue location is described as a screen location index, with no map to the grid or to screen coordinates. The trials table's Run and TrialNumber columns have no description, and the start time has only the NWB default description, though the decoding of the finger over time is consistent with the cue onset. The participant is P1 in the files and NS in the paper. Electrode coordinates are missing.
  • The first session has 64 No-Go trials; the paper's text says 84, but its own total of 4016 scored trials implies 64.
  • The two published versions hold the same files. The earlier one, which the authors' download script pins, names the preprint; the later one names the eLife paper.
