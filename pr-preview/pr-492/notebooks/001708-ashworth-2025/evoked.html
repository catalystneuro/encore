# Clock check: the spike trains and the event times share a clock. The withdrawal response of ON
# and OFF cells (rate in the 2 s after withdrawal minus the 2 s before) at the true withdrawal
# times is compared with the same contrast at times shifted by 60 s (labels shifted in time), per file.
def contrast(train, times):
    out = []
    for t in times:
        out.append(np.sum((train >= t) & (train < t + 2)) / 2 - np.sum((train >= t - 2) & (train < t)) / 2)
    return np.mean(out) if out else np.nan

fig1c-psth-counts: The population PSTHs of Figure 1c pool 70 ON and 60 OFF cells, with 185 ON and 155 OFF trials aligned to withdrawal and 182 ON and 151 OFF trials aligned to heat onset, for windows that run to 150 s.

fig2-trial-counts: For the models, windows from 10 s before to 100 s after the event gave 195 ON and 170 OFF trials aligned to withdrawal and 197 ON and 172 OFF trials aligned to heat onset; cells were not selected by pre-trial firing and every trial with a withdrawal was included.

The rule is the one the criteria give (Spike2Tools.get_all_event_spike_trains). Pinches: the criterion counts the next or previous pinch as an event that truncates a window. The code builds its event list from an event named "Keyboard", while its NWB loader renames the pinch events "keyboard" (data_loaders.rename_blocks_to_old_labels), so the code's list holds no pinch; both are run: "with pinch" (the criterion's rule) and "without pinch" (the code as it runs).

def mod_test(sel, cls, ev, pre, post, wp):
    tr = rvm.all_trials(sessions, sel, cls, ev, pre, post, wp)
    d = []
    for ci, t in tr:
        c = sel.loc[ci]
        x = sessions[c.session]["trains"][c.unit] - t
        d.append((np.sum((x >= 0) & (x < 2)) - np.sum((x >= -2) & (x < 0))) / 2.0)
    d = np.array(d)
    p = stats.wilcoxon(d).pvalue if np.any(d != 0) else 1.0
    return len(tr), len({c for c, _ in tr}), float(np.median(d)), float(np.mean(d)), float(p)

Model fits (withdrawal-aligned)¶

The models of the code (bayesian_cell_models.py), fitted to the summed counts of fig2-trial-counts (50 ms bins, -10 to 100 s, 2200 bins), NUTS with 4 chains, 1000 tuning steps and 1000 draws (Methods), target_accept 0.8 (the code's sample_model), seed fixed per fit. Every model is fitted to both trial sets: with pinch, the criterion's rule and the main reading (no suffix), and without pinch, the code's rule, which gives the paper's trial counts exactly (suffix _np). For the OFF linear plus exponential model, the main reading puts the Methods' priors k, k2 ~ N(0, 1) on k and k2 (taken as half-normal, since the sigmoid slope and the rate k2 must be positive), and the code's priors on log k and log k2 are a variant (_logk).

Where the chains start. These posteriors have local modes far below the main one: started at the model's default point, as the code starts them, some OFF chains stay in a mode whose log posterior is about 240 lower, and the pooled chains do not converge. Every model with a switch time is therefore started at the highest of nine local maxima of the posterior (pymc.find_MAP from nine switch times spread over its prior; rvm.map_start), with pymc's default jitter. This is a sampler setting, not a method: the paper does not say how its chains were started. The two OFF linear fits are also sampled from the default start (suffix _default_start), to show what it gives. For each fit the table below gives the mean log posterior of each chain, which shows whether any chain stayed in a lower mode.

The sampler's results depend on the machine. On one machine a run at these seeds is repeated exactly, but on another the floating-point differences change the draws: means move in the third digit, and a fit that converges on one machine can fail to on another (the verifier's execution had OFF_erf_linear_np unconverged, r_hat 1.393, and the default-start fit with two chains in the lower mode). The table marks a fit as converged when its largest r_hat is at most 1.01 and its smallest bulk ESS at least 400; conclusions use converged fits only, and the two erf fits with linear recovery are also sampled at target_accept 0.95.

def elpd_table(names, ic):
    cmp = az.compare({n: FITS[n] for n in names}, ic=ic)
    return cmp[["rank", f"elpd_{ic}", "p_" + ic, "elpd_diff", "se", "dse", "warning"]]

def pair(a, b, ic):
    """ELPD of a minus that of b, and the standard error of the difference (arviz.compare)."""
    cmp = az.compare({a: FITS[a], b: FITS[b]}, ic=ic)
    sign = 1 if cmp.index[0] == a else -1
    return sign * float(cmp.loc[cmp.index[1], "elpd_diff"]), float(cmp.loc[cmp.index[1], "dse"])

def timing(name, kind, grid):
    out = {}

How the analysis differs from the paper's. The chains of every model with a switch time start at the highest of nine local maxima of the posterior (multi-start MAP), a sampler setting the paper does not give; from the code's default start, the OFF fit with the Methods' priors does not converge. With that start every fit converges except the erf model with linear recovery on the main trial set, which converges at target_accept 0.95; the Methods' priors on k and k2 are the main reading, and the code's priors on log k and log k2 give the same outcomes. Every model is fitted to the criterion's trial set (pinches truncate windows) and to the code's (without pinches), which gives the paper's trial counts and, to within one unit, its ELPDs; both give the same outcomes. Fits differ between machines at the same seeds (third digit of the means; convergence of some fits), so the numbers quoted are those of this execution.

What was found about the dataset. The counts of cells, animals and trials match the paper.
