Reproducing Thompson & Gold (2026) from dandiset 002034¶

Paper. Thompson LW, Gold JI (2026). Limitations of pupil diameter as a proxy for modes of locus coeruleus activity. eLife reviewed preprint 112525, version 1 (2 October 2026), doi:10.7554/elife.112525. The claims file was written from the full text of that version as served by the publisher (main text, figure legends, Methods and the legends of Supplemental Figures 1 and 2).

Dandiset. DANDI:002034, version 0.261019.2146. The paper cites no version; its code's README names this one, and it is the only published version.

What the dandiset holds. 83 sessions (32 for monkey Oz, 51 for monkey Cicero, "Ci" in the paper), one NWB file each, with the trial table, the pupil trace of every trial and 105 sorted LC units. The paper reports 42 units from 32 sessions (Oz) and 63 units from 51 sessions (Ci).

Outside inputs. From the paper's code (https://github.com/lwthompson2/Thompson2026_LCPupilAnalysis, commit cf3c0b7): its include lists of sessions and units, compared with the dandiset in the link claim, and its printed statistics on this dandiset (Code/Results/manuscript_stats_nwb.txt), used only as reference values in the link claim. No outside data enters any other claim.

Readings. Every method detail is the claims file's, which cites the Methods and the code; the helper's docstring says where each parameter comes from. The deciding readings are the Methods' trial rule and windows with the evoked pupil read as E1 (largest window mean minus baseline) or E2 (largest in absolute size, sign kept). Variants: the code's trial rule and windows with its own evoked pupil (code), and two mixtures that isolate the evoked pupil window (code trials + E1, Methods trials + code pupil).

No random numbers are drawn anywhere in this notebook.

Spikes are stored outside the trials: about 40% lie before a trial's start, up to a few seconds before it (median about 0.8 s), but few lie after its end, and the rate falls from about 4.4 sp/s in the last 200 ms of a trial to under 1 sp/s in the 200 ms after it (numbers above). The spike record therefore runs from before the trial start to about its end. The pupil record has no samples after the end of the trial either. So on beep trials whose 200 ms evoked window runs past the end of the trial (printed above for each rule), the evoked rate is biased low. Both the Methods' rule and the code's keep such trials, so the main readings keep them as well; leaving them out is run as the variant "200 ms after beep" for every analysis below. It bears only on measures that use the evoked rate; for the pupil measures alone the trial set changes but no measure is biased.

That spikes are stored before the trial start does not tell what event the start marks. With the beep a median 2.2 s after the start and the Methods' beep after 1 to 1.5 s of fixation, the start may come before fixation onset, but the files hold no fixation marker to settle this. Every window is taken from the trial start, as in the code, which reproduces the paper's numbers.

How the analysis differs from the paper's. The deciding readings follow the Methods where they and the code differ (trial rule, the fixation-only window for the baseline rate, and the evoked pupil window), as the claims file directs; the code's pipeline is run as a variant and reproduces the code's printed output. The three claims that do not reproduce in full each pass only under the code's full reading, and no single difference explains all three. For the Oz range effect and the cross-epoch LLR counts, neither mixture of the two methods gives the paper's numbers: they need both the code's trial rule and its evoked pupil (0 to 800 ms after the beep, in place of the beep to 20 ms before the end of fixation). For the raw-baseline comparison, the cell that differs (row 6 in Ci, evoked LC against baseline pupil) does not use the evoked pupil; it passes only under the code's full reading, whose trial rule keeps 85 beep rows with the beep 7 to 69 ms before the end of the trial, where the 200 ms evoked rate is counted mostly past the end; without such trials the code reading fails it too.

Two assumptions underlie the outcomes. The trial start is taken as fixation onset for every window, as in the code; the files hold no fixation marker, and spikes are stored from before the start (data check), so what the start marks is not known. The stored pupil is taken as already preprocessed (z-scored per session), which the data check is consistent with; the Figure 3 claims pool pupil across sessions and so rest on it (pupil z-scored again changes them little). The paper's units and sessions cannot be told apart from the code's by the archive (63 and 51 for Ci in the paper, 61 and 50 in the code's output), and row 6 in Ci is fragile on this point.
