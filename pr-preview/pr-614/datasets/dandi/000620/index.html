Findings about the data

What attempts found about the dataset itself, for its owner and the archive.

  • Published code disagreesThe Methods (Feedback phase) say a response was correct within 2.4 degrees (0.1 arena widths) of the target; the paper's code scores correctness at 0.2 arena widths (4.8 degrees), and the data agree with the code: every completed trial with a closed-loop response error under 0.2 arena widths was rewarded (49,185) and none at 0.2 or more (12,469).
  • Paper inconsistentThe Methods say the cue phase lasted 180 ms and the Fig. 1c legend counts saccades earlier than 180 ms after cue onset as broken fixation; in the trials tables the response phase begins 250 ms after cue onset (0.2498 to 0.3167 s), 47.9% of completed trials have a response time under 250 ms, and 1.1% are under 180 ms yet are not marked as broken fixation.
  • Description missingThe trials column response_time is described as the response time from high-resolution eye tracking, without saying which event it marks; it precedes closed_loop_response_time by 134 ms at the median and in some completed trials precedes cue onset (earliest 12.5 ms before), so it reads as saccade onset.
  • Description missingThe electrodes tables of all spikesorting files give location 'unknown'; the brain area of each probe (s0 in DMFC, vprobe0 and vprobe1 in FEF) is stated only in the paper's code and the claims, not in the dandiset.
  • Selection not documentedThe dandiset holds two Perle sessions the paper does not count, 2022-06-06 (spike sorting, 2,378 trials, all with 2 objects, 77 units) and 2022-06-08 (behaviour only, 1,517 trials); neither the dandiset nor the paper says what they are. The paper's 22 Ring sessions include Elgar 2022-09-18 and 2022-09-19, which the code's Ring model comparison leaves out.

Method differences

How the tests differed from the paper’s method or data, and the claims each applies to.

  • Physiology sessions only (24 Triangle, 22 Ring); the behaviour-only session Perle 2022-06-08 and the 2-object-only session Perle 2022-06-06 are left out, as the Fig. 1b legend says all physiology sessions.fig1b-performance-load
  • Reaction time is response_time minus cue onset, as the code computes it; response_time reads as saccade onset (the closed-loop response time is 134 ms later at the median), which the paper's legend calls onset of the response saccade.fig1c-reaction-times
  • Assumed the correctness radius of 0.2 arena widths (4.8 degrees), the code's (load_triangle_data.py, correct_threshold 0.2, also used for response_location), where the Methods (Feedback phase) say 2.4 degrees. Reason: in the data every completed trial with a closed-loop error under 0.2 arena widths was rewarded (49,185 trials) and none at 0.2 or more (12,469 trials), so 0.2 is the radius the task used to score responses, and the code that made Extended Data Fig. 1 assigns responses to vertices with it. The Methods radius is shown and gives a different outcome for Monkey P with 2 objects.ext1-misbinding-errors
  • Errors at the target vertex but outside the radius cannot occur here, since the vertex radius equals the correctness radius; responses at no vertex and at an empty vertex are counted apart.ext1-misbinding-errors
  • DMFC is probe s0 and FEF the V-probes, from the claims file and the code; the dandiset's electrodes tables give no location.triangle-unit-counts
  • Perle 2022-06-06, which has spike sorting but only 2-object trials, is not counted as a Ring session; the Ring design has 1- and 2-object trials (Methods, Behavioral Task).ring-unit-counts
  • The stimulus phase is stimulus onset to delay onset, as the code computes it; it lasts 1.000 s at the median (0.9997 to 1.4167 s).ext2-stimulus-delay-activity
  • AUCs are not cross-validated; the Fig. 2b legend calls them cross-validated but neither the Methods nor the code says how (claims file, T6).fig2b-selectivity-range
  • AUC by ranks with ties as half; the code's trapezoid on value-sorted labels orders ties arbitrarily.fig2b-selectivity-range
  • The code's p-value (auc.py) resamples labels with replacement in the value-sorted order, a null of 5,000 draws, where the Methods shuffle 1,000 times; both are run. Counts of units entering the models under the code's p-value run above the counts its selectivity notebook printed for Elgar, for reasons not found.fig2b-selectivity-range
  • The Triangle reference for reaction-time variability is reading (a) of fig1c-reaction-times (Triangle trials on the triangle, trials at or above 180 ms).fig5ab-ring-behavior
  • The preferred angle is the peak of the mean of the 100 bootstrapped tuning curves; the Methods describe the curves, not how a preference is read from them.fig5cd-ring-tuning
  • AUCs are not cross-validated, as for fig2b-selectivity-range.fig5cd-ring-tuning
  • Code variant vectorised: the within-condition shuffle permutes trials for all units at once and each pair's shared trials are taken after it, where the code keeps the pair's shared trials first and then shuffles.fig2d-signal-noise-triangle
  • Intervals are normal 95% intervals of the mean, a standard choice; the paper's plots use seaborn's bootstrap interval.fig2d-signal-noise-triangle
  • Units above 1 Hz (T5); the code's run_compute_ring.py takes every unit of its selectivity table.fig5e-signal-noise-ring
  • Neighbours within each pair's shared trials are taken from one distance sort per session; ties among equidistant trials are broken by trial order, which can differ from the code's argsort.fig5e-signal-noise-ring
  • Methods reading (a) uses the 10 nearest neighbours without the trial itself, as the code does for reading (b).fig5e-signal-noise-ring
  • The decoders are models.py's LinearModel1Object written in numpy (wm.train_linear) with the configs' settings (panel a SGD lr 0.01, panel b Adam lr 0.001, L1 0.003, batch 512, 10,000 steps), batched over splits; torch's random streams are not reproduced.ext3ab-decoding
  • Inputs are rates in Hz with no per-unit normalisation, as the code's dataset.py, where the normalisation lines are commented out ("# Normalize neural data").ext3ab-decoding
  • Units entering the models are selected with the Methods' AUC p-value; this picks the same sessions as the code's scripts name. Ten seeds as the legend says, where run_1_triangle.py lists twenty.ext3ab-decoding
  • The code's filters (dataset.py, units with 50 trials, trials with 5 units, then greedy removal to a fully observed matrix, which with keep_units_weight 1.0 drops units before trials) leave 105 to 121 1-object trials, and 104, 82 and 20 units; for 2022-06-04, 72 of 116 units have 50 trials and 20 are kept.ext3ab-decoding
  • LinearModel2Objects written in numpy (wm.train_linear_2obj), Adam lr 0.001, L1 0.003, batch 512, 10,000 steps (config_2_triangle.py, config_2_ring.py); synthetic datasets as dataset.py with numpy's generator.ext3c-decoder-orthogonality
  • Assumed: as in models.py the Ring decoders keep the sigmoid output, though the Ring targets 2x - 1 and 2y - 1 (labelers.py) lie in -0.7 to 0.7, while the Methods (2-object decoder) say "The variables W 0 , B 0 parameterize one linear decoder" and give no output function. The code's decoder is taken because it is the method that produced the paper's figure; the outcome rests on this, since with a linear output the Ring neural data fail (notes). Inputs are rates in Hz, as dataset.py.ext3c-decoder-orthogonality
  • Ring sessions Perle 2022-06-10, 06-11 and 06-09, ranked by units entering the models with the Methods p-value, the sessions run_2_ring.py names.
