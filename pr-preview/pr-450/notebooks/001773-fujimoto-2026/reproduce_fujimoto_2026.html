Dandiset. DANDI:001773, version 0.260416.1939. This is the version the paper cites in its Code availability statement (doi:10.48324/dandi.001773/0.260416.1939), as the claims file gives it. A later version, 0.260615.1838, holds the same 54 assets with the same asset ids (shown in the data check), so the choice does not change the data.

The dandiset holds the paper's derived values as Excel sheets (voxel FA, voxel seed connectivity, group connectomes, cell counts, g-ratios, behavior bins) and its MATLAB analysis scripts. The sheets are read into memory from the archive; the analyses follow the scripts (see dbs.py). No random numbers are used anywhere.

Data check¶

The dandiset holds Excel sheets of derived values and the paper's MATLAB scripts; no images or time series. Each check of the metadata against the values is stated under its output. With no time series there is no clock to align; the corresponding check is that the condition labels mean what the legends say. Side is checked against the hemispheres (voxel sheets with coordinates, the NMT-space voxel counts, the EM image labels), and pre and post against the session dates of the seed tables; pre and post cannot be told apart from the values themselves, so those labels are taken as the sheets give them, which the reproduced statistics are consistent with.

The voxel counts per side are the NMT-space left and right counts swapped between N and T, so side 1 is each monkey's stimulated hemisphere, as the claims file reads it; pooled over N and T they match the Supplementary Table 8 sums used in the claims (for example DMN below 857 per side), and monkey D's left plus right count equals the pooled count of each side. The rows give the error df of the paper's models (20,348 and 10,174 values). The values are all Fisher Z divided by each session's maximum, so most lie near 0 and the largest near 1. Each voxel has one value per session (the date column numbers the sessions, four for N and T and two for D), and the script analyses the sheet as it is, with no run index. The deposited maps are therefore one per session. The file names say "concatenated", which may refer to runs or to the subjects and ROIs combined in one sheet, and the paper does not say whether runs were concatenated or their maps averaged. Only this one version can be run (see deviations); its interaction F values are the paper's. There are no seed values for the nonsurgical controls B, W and H.

fig4b-roi-changes-counts¶

Per ROI, functional connectivity changed significantly between pre and post scans in 69 of the 123 CHARM and SARM ROIs in the DBS group and in 44 of 123 in the nonsurgical control group.

The criterion, amended after the reader's answer of 2026-11-03, is the test of the paper's Fig. 4 script: for each of the 123 ROIs, a two-sided rank-sum of its 122 off-diagonal changes against 122 zeros, ranksum(sbj_data_mean, zeros(length(sbj_data_mean),1)), counted when P < 0.05/123 (the script's 0.05/nrois). The rank-sum is computed as MATLAB ranksum does for these sample sizes (normal approximation with tie correction and continuity correction, scipy.stats.mannwhitneyu, method "asymptotic"). The tolerance is 62.1 to 75.9 (DBS) and 39.6 to 48.4 (controls).

Reported as variants, not judged on: the Methods' threshold P < 0.01/123, a rank-sum of the ROI's pre values against its post values, and a signed-rank test of its changes against zero; also the thresholds 0.01/122 and 0.01 uncorrected, and the values with the ROI's own diagonal, which the earlier criterion named.

def mw(a, b):
    return stats.mannwhitneyu(a, b, alternative="two-sided", method="asymptotic", use_continuity=True).pvalue

def roi_pvalues(c, keep_diag):
    n = len(c["pre"])
    out = {}
    out["a rank-sum pre vs post"] = np.array([mw(dbs.offdiag(c["pre"], i, keep_diag), dbs.offdiag(c["post"], i, keep_diag)) for i in range(n)])
    out["b signed-rank change vs 0"] = np.array([stats.wilcoxon(dbs.offdiag(c["diff"], i, keep_diag), zero_method="wilcox").pvalue for i in range(n)])
    out["code rank-sum change vs zeros"] = np.array([mw(dbs.offdiag(c["diff"], i, keep_diag), np.zeros(n - 1 + keep_diag)) for i in range(n)])
    return out

How the analysis differs from the paper's. The tests are those of the paper's MATLAB scripts in the dandiset, reimplemented in Python: type III ANOVA with sum-to-zero coding and the scripts' model terms, Tukey-Kramer on population marginal means, MATLAB's tie-corrected rank-sum. The ANOVAs give the reported F values to two decimals throughout. The Tukey-Kramer P values are within 3% of the reported ones above 1e-4, 1.12 to 1.14 times them near 1e-5 and 1.11 to 1.28 times near 1e-6 (table before this summary). Below 1e-7 SciPy's studentized range tail is inexact: 1.5 to 2.8 times the reported value between 5e-9 and 4.4e-8, 5.5 and 8.3 times for the reported 8.22e-12 and 1.37e-12, and it stops near 1e-11 or at 0 where the paper prints 0. No such P is near 0.05. The deposited seed maps are one per session, and the paper does not say whether its runs were concatenated or averaged, so only one of the claims file's two run readings can be run; the seed connectivity outcomes assume the deposited maps are those the paper analysed, which the reported F values support. The per-ROI connectome counts use the test and threshold of the paper's Fig. 4 script (rank-sum of the changes against zeros, P < 0.05/123), as the claims file has them since a reader's answer; they differ from the Methods' "P < 0.01 with Bonferroni correction".
