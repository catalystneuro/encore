Reproducing Mannion (2015) from CRCNS vim-3¶

Paper. Mannion DJ (2015). Sensitivity to the visual field origin of natural image patches in human low-level visual cortex. PeerJ 3:e1038. doi:10.7717/peerj.1038. The claims file (claims/crcns-vim-3/10.7717-peerj.1038.yaml) was written from the version of record (PMC4485252); the supplementary files themselves were not available, only their legends.

Data set. CRCNS vim-3, doi:10.6080/K0JS9NC2, read from the public bucket at https://crcnsarchive.s3-us-west-2.amazonaws.com/vim-3/. CRCNS data sets are not versioned (docs/archives.md), so the version is recorded as unversioned, and the paper cites the data set by its DOI only. The data set has one data file, crcns_vim-3.tar.gz (2,349,486,063 bytes), with md5 005760a76158d4f16f54b41ee24cd1f2 in the data set's checksums.md5; the notebook streams the whole file once, computes its md5 as it reads and compares it with that list below, so a later change of the file is detected. The data descriptor is version 0.5 of 12 June 2015. There is no other version to choose. A tar.gz has no index, so it cannot be opened in place as a zip can; it is streamed member by member and nothing is written to disk.

What the data set holds. For each of the seven participants, the ten functional runs (NIfTI, not preprocessed), the event sequence of each run, the digit stream of the central task and the button presses; and screenshots of the 120 stimuli. It does not hold the anatomical images, the cortical surfaces, the retinotopic mapping or the V1, V2 and V3 definitions; the descriptor says so ("You may need additional data (anatomical images, visual area definitions, etc.) that are not part of the current archive"). Every response claim of the paper is measured in V1, V2 and V3.

The blocked response claims are not tested. To describe the data set, the data check fits the paper's GLM in the volume, and a last section repeats the response analysis on a volume localiser region that is not V1 to V3. No outcome rests on that section. The radial-bias test needs only the stimulus screenshots and the monitor calibration; it is run under two assumed calibrations, as a variant on which no outcome rests.

The archive holds 280 files under the seven participant directories, 120 under stim/ and one README.txt at the top (the listing above counts every member, so nothing is skipped unseen); there are no anatomical, surface or area files. The descriptor says each participant directory holds the 10 fMRI recordings with the sequence and task files; every directory holds 10 NIfTI files, 10 sequence, 10 task and 10 task lookup files. Each NIfTI is 96 x 96 x 35 voxels by 166 volumes, 2 mm voxels, int16 with a scale factor, which matches the Methods (matrix 96 x 96, 35 slices, 2 mm isotropic, 332 s at TR 2 s). No two files share their content, and no run sequence is repeated, so no recording was deposited twice. The NIfTI files are named by scanner series number, not run number; for p1003 and p1010 the series run 3, 4, 6 to 13 and 4 to 13. Run n is taken to be the n-th series in order, which is what the participant configurations of the paper's code list (for example p1003 [3, 4] + range(6, 14)); the check of the run order below tests this against the data.

Each field's sequence has 83 events at 4 s steps, of which 8 are marked 'pre' (the Design: 83 events, 4 s inter-event interval, the final 8 events replicated and prepended). In every run and field the other 75 hold 15 null events and 60 image events, 30 above and 30 below, each of the 60 image and source pairs once, as the Design says; the 30 image ids are those of the 120 screenshots (30 images by 2 sources by 2 presentation locations). The screenshots are 1920 by 1200 pixels, the display resolution of the Methods. Every screenshot holds pixels whose R, G and B values differ (by up to 192 levels); this count covers the whole screen, overlay lines included. The colour of the patches themselves is shown in the radial-bias section below, inside the patch masks. In every run one field's sequence starts 2 s after the other's, as the Design says, and which one varies by run. The task lookup has 996 digits at 3 Hz over 332 s, as the descriptor says and the Methods' 3 Hz stream. Button times lie within the run; four different keys were used, and task.py counts any key as a response, as is done here.

The next checks fit the paper's GLM in the volume, without the paper's preprocessing (no slice timing or motion correction, no projection to the surface) and with ordinary least squares in place of 3dREMLfit. They test that the image sequences share the clock of the fMRI volumes and that the NIfTI order is the run order. For each run, a localiser mask (voxels with t > 2.58 for one regressor for all image events of a field, as in the Methods, Localiser) is made from the other nine runs, and the mean over that mask of the held-out run is fitted with: each run's sequence (run order); its own sequence shifted by -12 to +12 s (clock); and the other field's sequence (contrast between conditions: the two fields' events alternate every 2 s, so a voxel set chosen for one field should follow that field's timing better than the other's).

How the analysis differs from the paper's. The tested claim follows task.py and group.py, with the ANOVA computed as paired contrasts (exact for a 2 x 2 design) in place of the code's fmri_tools routine. The radial-bias variant follows imstats.py with assumed monitor calibrations in place of the measured one, and OpenCV's Gabor kernel and filter written out in numpy and scipy (checked against OpenCV above). The volume checks and variant use OLS without slice timing or motion correction, in the volume, without the V1 to V3 restriction.

What was found about the data set. The archive holds the functional runs, event sequences and task files of all seven participants, with no duplicated recording, and its file matches its listed md5. It lacks the V1, V2 and V3 definitions, the cortical surfaces and anatomical images, which 14 of the 16 claims need directly or through the claims they depend on; it holds the stimulus screenshots but not the monitor calibration needed to put them in DKL space, so the radial-bias test, which needs nothing else, is blocked too, and 15 claims are blocked in all. The NIfTI files are named by scanner series, not run, and the descriptor does not give the mapping; the paper's code does, and the data support it for six participants. For p1011 the clock and run order could not be confirmed in uncorrected volume data, and that participant moves more than the others.
