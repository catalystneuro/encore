Do the deposited data support the paper?

Encore tests each finding of a paper on the data its authors deposited. You get a report of what reproduced, what did not, and what is missing from the dataset, with the code behind every result.

The method

Each check follows a written protocol, in a fixed sequence of roles. The readers, the author and the verifiers are separate runs that do not share their reasoning.

  1. The claims are written from the paper

    A reader agent records the paper's key findings as claims, each with the numbers it rests on, a tolerance, and the test that will decide it. A second reader checks them against the paper. The claims are fixed before any analysis is run, and the readers never see the data.

  2. Each claim is tested on the data

    An author agent checks the dataset against its own description, then writes a notebook that streams the data from the archive and tests each claim. What it learns about the data along the way is recorded as findings.

  3. An independent agent verifies the work

    A verifier, in a separate run that has not seen the author's reasoning or conclusions, reviews the notebook and the paper and decides its own outcome for each claim. The author answers each point and revises the analysis.

  4. The result is a record anyone can check

    Every claim has an outcome and the reasoning behind it. The notebook runs again in a clean environment, and the agents' transcripts are kept with the record.

  5. The paper's authors can respond

    An author of the paper who thinks a check is wrong, or who has something to add, responds from the paper's page. Once we confirm who wrote the response, it is shown there with the check, and a new check is run with what the response adds.

The report

An outcome for every claim

  • ✓ReproducedThe result matches the claim.
  • ◐Partially reproducedThe effect is present but weaker, or holds only in part.
  • Not reproducedThe analysis ran and the result differs. This may be a failure of the attempt.
  • ⊘BlockedThe claim could not be tested, most often because data it needs are not in the dataset.

Findings about the data

The agents record what is wrong with or missing from the dataset as they work: units that do not match, metadata that is missing, data the paper describes but the files do not hold. The most common kinds so far:

  • Metadata error664
  • Description missing657
  • Data missing443
  • Selection not documented131

Notebooks that run

Each check leaves the notebook that tested the claims. It streams its data from the archive and computes every result from them, so anyone can run it again or build on it.

Reading an outcome

A failure to reproduce is not a finding that the paper is wrong. An outcome says what one attempt could recover from the data in a dataset, with the methods available to it. A claim may fail to reproduce because of a mistake or a limitation in the agent's analysis, because the paper does not describe its methods fully, or because the dataset differs from what the paper analysed.

Most checks are made by AI agents, and the agents make mistakes. Every record links to its code and its reasoning, and an author who thinks an attempt is wrong can respond to it; the response is shown on the paper's page. More on reading outcomes

Built by CatalystNeuro

Encore Science is built by CatalystNeuro, a team of research software engineers who trained as neuroscientists. CatalystNeuro converts lab data to the NWB standard and publishes them on the DANDI Archive.

We believe recent advances in AI make it possible to raise the standard for open science: for the first time, the reproducibility of computational results can be checked at scale. Encore Science is our first large step in that direction.

Encore is led by Ben Dichter, founder and CEO of CatalystNeuro.

Open by design

The protocol the agents follow, the code that runs them and the transcript of every run are public. The code is under the Apache-2.0 license and the registry's records are in the public domain.
