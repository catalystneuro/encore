  • ✓1 reproduced

The paper's main findings held up in this data. Baseline LC firing and baseline pupil covary, as do evoked LC and evoked pupil responses, and each evoked response falls with its own baseline. Neither baseline reliably predicts the other signal's evoked response, per unit (Figure 2) and pooled (Figure 3), assuming as the paper's code does that the files' trial start marks fixation onset. Of the minor analyses, the raw-baseline control held in part, while a link between baseline LC and the range of evoked pupil in one monkey and a linear against quadratic fit comparison did not reproduce. Both appear only with the code's evoked pupil window and trial rule, which differ from the Methods.

Notes on the paper

What the attempts found about the paper itself: a method or rule it does not give, a place where it disagrees with itself, published code that does something else. What they found about the data is on each dataset’s page.

  • Published code disagreesThe code's include list already lacks units 43 and 65 of the legacy numbering (its unit_id runs 1 to 107 without them), and prepare_figure_analysis_tables.m (build_stats) then removes rows 43 and 65 of its own 105-row table again, which drops CiCM101019d unit 1 and Ci_LC_d14_6mm_SC_123107 unit 2. This is why the code's printed output has 61 Ci units and 50 Ci sessions for some analyses against the paper's 63 and 51.
  • Published code disagreeszscore_tables.m z-scores firing rates per value of the within-session unit index (unit 1, 2 or 3) pooled across all sessions and both monkeys, not per unit as the Figure 3 legend says (z-scored separately for each session/unit). Run here this way, the code's pipeline gives all 12 of the code's printed Figure 3 pooled coefficients to their three decimals; z-scored per unit, 2 of 12. Per unit the conclusions are the same.
  • Published code disagreesThe code measures the evoked pupil over 0 to 800 ms after the beep with a centred 50 sample moving mean, where the Methods give 50 ms windows in 10 ms steps from the beep to 20 ms before the end of fixation; it keeps beep trials more than 400 ms after the trial start and 800 ms before the end of the NaN-padded pupil record, where the Methods ask for 100 ms of baseline, so it keeps trials whose beep falls near or after the end of the trial (those after the end have no evoked pupil and enter no table, but 85 beep rows with the beep 7 to 69 ms before the end do); and it counts fixation-only baseline spikes to the end of the trial, not 20 ms before it. Under the Methods' measures two claims do not reproduce (the Oz range effect of rho = -0.33 and the cross-epoch LLR counts) and a third only in part, while the code reproduces the paper's numbers. On those 85 rows most of the 200 ms evoked rate window lies past the end of the trial, where spikes are mostly not stored, so their evoked rates are likely biased low; without beep trials whose 200 ms window runs past the end, the code reading no longer reproduces row 6 in Ci with raw baselines (p = 0.12, Supplemental Figure 1). Question for the authors: which window and trial rule produced the reported numbers?
  • Paper inconsistentThe Results name a Wilcoxon rank-sum test for the one-sample hypothesis that the median coefficient is 0; the code runs the signed-rank test (signrank), whose p-values equal the printed ones. The Results also relate the coefficients to the range in each session, while the code takes the range per unit.
  • Methods not availableThree choices that the outcomes here rest on are assumptions, asked of the paper's authors. First, which event does the trial start in the files mark? Every window is taken from it as fixation onset, as the code does, but the files hold no fixation marker, the beep falls a median 2.2 s after the start against the Methods' 1 to 1.5 s of fixation, and 39% of spikes are stored before it. Second, is the stored pupil trace already z-scored per session, with the mean trace subtracted and smoothed, as the Methods describe? The values are consistent with it, and the pooled Figure 3 coefficients rest on it. Third, which units and sessions did the paper use: its 63 units in 51 Ci sessions, or the 61 in 50 of the code's output? Row 6 in Ci is fragile on this point.
