  • Description missingPartly fixedThe electrodes table gives no position for the recording sites, only each channel's place in its shank's list in the lab's .xml file, and does not say which place is which depth. The DS2 profile in list order is smoother than under random orders on 0.83 of the 261 shanks where it reverses (0.05 by chance), so the lists are in depth order on most shanks, but their direction is not stated, and the amplitude rises with the list place on some shanks and falls on others (Spearman below 0 on 0.43), which a shank reaching the infrapyramidal blade could explain. The probe description names 8 shanks of 8 sites 20 um apart, but six mice's shanks hold 10 sites and YutaMouse33's probe has 10 shanks; the paper's Methods give the same 20 um vertical separation for the 10-site shanks. A user can read the site depth from the list place with the lab's convention (first place at the top), which the files do not state.#

    Found by the attempt on Senzai et al. 2017 (senzai-2017-02, 2026-11-23)

The files do not say whether the stored waveforms (the lab's .spk files) were filtered; neither the units table's description nor the waveforms' attributes state a filter. One file (YutaMouse33-150218) has no stored waveforms, as its description says.#

  • File format errorFixedIn 24 files the end index of the first unit in the units table is short by a multiple of 65,536 spikes (k = 1 to 7). The missing spikes open the second unit's spike train, which then restarts at the beginning of the recording, so the second unit's times are not sorted. The first moved spike follows the first unit's last stored spike by 2 ms to 0.5 s. This looks like an integer overflow at conversion; the waveforms follow the same boundaries.
    In earlier_findings.ipynb no unit's spike times decrease in any of the 101 files (0 of 4216 units), where the overflow had made the second unit's train restart in 24 files. Found fixed on dataset version 0.261122.2143 by senzai-2017-02, 2026-11-23.
