Findings about the data

What attempts found about the dataset itself, for its owner and the archive.

  • Data missingThe dandiset holds one session of one of the paper's three monkeys (monkey I, M1 array, 649.1 s with kinematics), released for the Neural Latents Benchmark. The paper used 49 sessions. The file dates the session 2017-02-02, which is not in the paper's list of monkey I sessions (NeuralAnalysis/Indy_HC_Sessions.csv, ending 2017-01-31), so it is probably not one of the paper's sessions, though the dandiset names the paper as describing it. The paper's own sessions are on Zenodo (doi:10.5281/zenodo.583331). The paper's tests across sessions cannot be run on the dandiset.
  • Data missingThe units table holds sorted units only (ids are channel times 100 plus 1 to 4). The paper kept an unsorted hash unit for every channel and counted them among its 171 to 413 units per monkey I session; without them 111 units pass the 0.5 Hz cut.
  • Selection not documentedThe training file has three gaps of 0.1 s (162.2 to 162.3, 324.5 to 324.6 and 486.8 to 486.9 s) where every behavioural series is NaN and no unit has a spike, splitting it into four segments; neither the file nor the dandiset says what was removed. The test file (190.3 s, 98 units) has no kinematics, so it cannot be used to score decoding.
  • Published code disagreesThe Methods decode the fingertip position low-pass filtered at 10 Hz and subsampled per bin; the paper's code (getLatentsBMI.m, binSpikeCounts.m) decodes the cursor position with the filter commented out and averages each bin. The two readings change the outcome of fig2-velocity-boost. Question for the paper's authors, which kinematics were decoded?
  • Published code disagreesThe Results say the standard-normal rEFH variant was trained on standardized spike counts; the code (getLatentsBMI.m) feeds it 2 sqrt(R + 3/8). The two readings change the outcome of fig8-gaussian-still-beats-ukf. Question for the paper's authors, which input was used for figure 8?
  • Methods not availableThe UKF follows Li's UKF2 package (fit_ar_ukf_hist_rrcv.m, ar_ukf_hist.m), which the paper's repository calls but does not hold; the attempt re-implemented it from the paper's description (linear state transition, tuning to the six states, their magnitudes and the position-velocity products, regression with full noise covariances, standard unscented transform). Question for the paper's authors, can the UKF2 code and its ridge setting be published with the paper's code?
