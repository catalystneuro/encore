Feature extraction¶

Each file is read whole into memory from the archive (about 70 s for the 12.4 GB at the speeds seen while preparing) and run through IPFX: sweep QC, then IPFX's long-square analysis on the sweeps that pass. The sweep QC is the Methods', as the link criterion asks. IPFX 2.1.2's own sweep QC applies only the noise limits (and a Vm-delta limit); the bias current (0 +/- 100 pA) and bridge balance (below 20 MOhm and 15% of input resistance) limits of the Methods are added here (patchseq_l23.METHODS_SWEEP_QC), with the input resistance of IPFX's cell QC for the 15% limit. The features under IPFX's sweep QC alone, which the first round of this attempt used, are kept as a variant. The 18 features are read from IPFX's output as patchseq_l23.FEATURE_SOURCES says. This took about 7 minutes on four processes in the last run (printed below).

def _one_split(X, y, seed, shuffle):
    r = np.random.default_rng(seed)
    yy = r.permutation(y) if shuffle else y
    Xtr, Xte, ytr, yte = train_test_split(X, yy, test_size=0.3, stratify=yy, random_state=int(seed % 2**31))
    clf = RandomForestClassifier(n_estimators=600, class_weight="balanced", max_features="sqrt",
                                 min_samples_leaf=2, n_jobs=1, random_state=int(seed % 2**31))
    return float((clf.fit(Xtr, ytr).predict(Xte) == yte).mean())


def rf_accuracy(d, claim, n_splits=1000, shuffle=False, feats=F):
    """Mean test accuracy over stratified 70/30 splits, features standardized over all cells.

    Cells with a missing electrophysiological feature are dropped (the code drops them); `feats` are the
    columns used."""
    d = d[d[F].notna().all(axis=1) & d[feats].notna().all(axis=1)]
    X = StandardScaler().fit_transform(d[feats].to_numpy(float))
    y = d.tt.to_numpy()
    seeds = rng_for(claim + ("-shuffled" if shuffle else "")).integers(0, 2**63 - 1, n_splits)
    acc = np.array(Parallel(n_jobs=4)(delayed(_one_split)(X, y, s, shuffle) for s in seeds))
    return acc, d.tt.value_counts()

How the analysis differs from the paper's: The files carry no SpecimenID; cells were matched to the code's table through the session id (the next SpecimenID of the same donor, reading M2 of the link), which the features confirm for 261 of the 283 cells with features in the code under the Methods' sweep QC (a match on features alone picks the same cell for 261 of 261) and for 282 of them under IPFX's sweep QC alone (282 of 282), and the sample dates and tube order support for the 35 cells without features in the code; one of the 283 gives features under neither QC, and its date matches; under M1, a SpecimenID stored in the files, no cell links. Features were computed with IPFX 2.1.2 (the paper gives no version) and read from its output as the code's feature names imply. The sweep QC is the Methods', with the bias current and bridge balance limits that IPFX 2.1.2 does not apply added, and the input resistance of IPFX's cell QC for the 15% limit, a choice the Methods do not fix; IPFX's sweep QC alone matches the code's table more closely. No cell QC is applied, as the claims file asks. The analysis cells are every file whose matched cell has the feature, which adds 19 cells to the code's 283 and loses 22 of them; the section on cell sets gives every electrophysiology outcome on the 283 alone, with cell QC and with IPFX's sweep QC. Labels, pathology scores and the mouse features come from the code's tables, which are from the paper's revision. Code6 and Code7 were ported to Python; for mouse, the port reads the boundary lines and pixel scale in the way that gives Code7's printed values, not as Code7's code is committed. The morpho-electric classifier runs 250 splits, not 1000, to keep the notebook within 30 minutes.

What was found about the dataset: It holds 318 recordings from 56 donors: every one of the 283 cells with features in the paper's code, and 35 more of the code's 385 cells; 67 cells of the table are not in it.
